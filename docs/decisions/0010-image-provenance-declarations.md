# 0010: Which image provenance claims count as "Made with AI"

**Status:** accepted (2026-11-10)

## Context

An image file can say it is AI-made in several ways, with very different strength: a C2PA manifest signed by a trusted certificate, a C2PA manifest signed by an unknown certificate, an unsigned IPTC "trainedAlgorithmicMedia" code in XMP metadata, or settings left behind by an image generator. Manifests can also be broken: the pixels changed after signing, or the signature does not verify.

## Decision

| What the file contains                                                | Outcome        | Shown reason                                                                          |
| --------------------------------------------------------------------- | -------------- | ------------------------------------------------------------------------------------- |
| Intact C2PA manifest, trusted signer, declares AI                     | Made with AI   | Signature says an AI tool made it                                                     |
| Intact C2PA manifest, signer not recognised, declares AI              | Made with AI   | Same, plus "we do not recognise who signed it"                                        |
| Unsigned IPTC AI code in XMP, or generator settings                   | Made with AI   | "The file says it was generated by AI" / "contains settings left by an AI image tool" |
| Intact C2PA manifest, no AI declaration                               | No clear signs | "It has a digital signature that does not mention AI"                                 |
| Broken C2PA manifest (hash or signature mismatch), whatever it claims | No clear signs | "The signature is broken or changed"                                                  |
| Nothing                                                               | No clear signs | none                                                                                  |

- Unsigned and unrecognised-signer declarations are accepted because the realistic risk is small: people rarely label a real photo as AI. The reason text always says which kind of evidence it was.
- A broken manifest proves nothing either way, so its claims are ignored. The simple metadata scan only reads the AI code inside XMP packets, never inside the manifest, so a tampered manifest cannot count through the back door (a test covers this).
- An intact manifest with no AI claim is **not** shown as "real" or "authentic" (ADR-0002). It is context only.
- Validation runs offline with the official C2PA library (`@contentauth/c2pa-node` in Node; `@contentauth/c2pa-web` planned for the extension). Remote manifests are not fetched (ADR-0003).

## Consequences

- Someone can falsely label a real photo as AI by adding metadata. Accepted for now; revisit if it is seen in practice.
- No trust list is loaded yet, so every signer is currently "not recognised". Loading the official C2PA trust list is a follow-up within M3.
- Composite images (a photo with an AI-generated part) are reported the same as fully generated ones. Telling them apart is a later refinement.
